# C4 — Agent 與多步推理（ReAct + 錯誤重試 + 停止條件）

> 時長：1 hr　|　投影片：`class-04-...pptx`（核可後產）　|　Lab：`lab-04.md`
> 交付：寫一個 **3+ 步 ReAct 迴路**，含**錯誤重試**、**停止條件**、**成本閘門**，做出不會失控的多步代理。

---

## 1. 這堂要解決什麼

C3 是「**一次**工具呼叫」；C4 是「**一串**工具呼叫，且要**自己決定**下一步」。
這就是 **Agent**：面對一個**多步驟目標**（例：「幫我訂一張最快、最便宜的東京機票，並寄 email 給 Bob」），LLM 要：
- 判斷先做什麼、再做什麼（**規劃**）。
- 執行一步、看結果、**決定下一步**（**觀察→再決策**）。
- 卡住時**重試或換路**（**錯誤處理**）。
- **知道何時該停**（**停止條件**）——不然就是刷 token 到破產。

> **心智模型**：Agent＝**受約束的迴路**（bounded loop）。
> 沒約束的迴路叫「失控」：死循環、重複工具、無限思考、成本爆炸。
> **好的 Agent＝「會做事」＋「知道何時收手」＋「出錯會調整」三者兼具**。
> 前兩者（做事）C3 已給；本卡補後兩者（停止、重試）——**這才是 Agent 能不能上生產的差別**。

**驗收口**：一個跑通 3+ 步、含 1 次錯誤重試、並在正確時機停止的 agent trace。

---

## 2. ReAct 迴路（Thought → Action → Observation）

Agent 最常見的心智架構＝**ReAct**（Reason + Act），每個 cycle：

```
Thought:   我現在該幹嘛 / 為何選這個工具
Action:    呼叫哪個工具、參數是啥（= C3 的 function call）
Observation: 工具回傳的結果
（重複，直到達成目標或触停止條件）
Final Answer: 給使用者的最終回應
```

**例（訂機票 agent）**：
| 步 | Thought | Action | Observation |
|----|---------|--------|-------------|
| 1 | 要先查有哪些航班 | `search_flights(taipei→tokyo, 10-20)` | 3 個航班 |
| 2 | 挑最便宜的 | `get_price(flight_2)` | NT$12,000 |
| 3 | 要確認有沒有座位 | `check_seat(flight_2)` | 有 4 席 |
| 4 | 達成目標 | **停止**，回最終答案 | — |

> **心智模型**：ReAct＝**「想一步、做一步、看結果、再想下一步」**的循環，像工程師除錯：**假設→實驗→觀察→修正**，而不是一口氣把所有步驟寫死。
> 「把步驟寫死」＝**workflow**；「動態決定下一步」＝**Agent**。本卡做後者。

---

## 3. 三大約束（Agent 不失控的關鍵）

### 3.1 停止條件（stop condition）
- **目標達成**：LLM 決定「完成」→ 出 final answer。
- **最大步數**（max steps）：例如 8 步——**硬閾值**，防死循環。
- **成本閘門**（budget cap）：累積 token/費用超過門檻就停＋報警。
- **無進展偵測**：連續 N 步 Observation 無變化 → 判定卡住、停止並回報。

### 3.2 錯誤重試（retry）
- 工具回 `error` → LLM 收到後**自行**決定：換參數／換工具／換路／回報。
- **重試要有上限**（例 3 次）＋**指數退避**（rate-limit 時）。
- 重試**改變策略**而非重打同一發（同樣參數重試 10 次=白費）。

### 3.3 狀態管理（memory）
- Agent 要**記住**前幾步 Observation（放進 `messages` 歷史）。
- 長任務要會**摘要**歷史（省 token），只保留必要事實＋目標。

> **心智模型**：三個約束＝**「會收手」＋「出錯會換」＋「記得做過了什麼」**。
> 缺哪個 Agent 都會翻車：缺停止→刷爆成本；缺重試→一錯就整條掛；缺記憶→重複做同一件事。

## 4. 工具選擇與決策品質

Agent 強弱的分水嶺＝**選對工具的決策**：

| 決策品質差的 Agent | 決策品質好的 Agent |
|--------------------|--------------------|
| 每步都亂抓一個工具 | 先想「這步目標」再選工具 |
| 忽略 Observation，重複同工具 | 讀 Observation 調整下一步 |
| 一次只推進一步（人肉 driver） | 合理拆步驟（不貪多、不少步） |
| 目標模糊就開跑 | 先**拆解目標**成可驗證子步 |

**技巧**：
- 讓 LLM **先規劃**（列 3–5 步計畫）→ 再逐步執行（planning-then-acting）。
- 每個工具的 `description`（C3）寫好＝**給 LLM 選路的說明書**。
- 限制每步**只允許**相關的子工具集（縮小選擇空間，降低選錯率）。

> **心智模型**：Agent 的「聰明」不在模型本身，而在**「目標拆解 + 工具選擇 + 讀 Observation 調整」這三件事的品質**。
> 這三者都可**工程化**（prompt 結構化、schema 精確、歷史管理），不必靠「換更強模型」。

## 5. Agent 失控案例（避坑）

1. **死循環**：LLM 反覆呼叫同一工具、Observation 無變化 → 沒設 max steps／無進展偵測。
2. **成本爆炸**：沒 budget cap，一次死循環刷到 US$500+（C0 成本估算法在此兌現）。
3. **误操作**：讓 LLM 直接「執行」高風險 action（刪 DB / 發 email）且**無人工確認門** → 要**人審高風險動作**（C6 上線會講）。
4. **無限思考**：thought 越寫越長、不產出 action → 限制每步長度／強制要 action。
5. **忽略 Observation**：工具回錯但它沒讀，繼續下一步 → prompt 要求「先讀 Observation 再決策」。

> **心智模型**：失控 Agent 的三宗罪＝**不知手（沒停止）＋ 不怕錯（沒重試）＋ 不記事（沒記憶）**。
> 修法是**加約束**，不是「換更大的模型」——約束才是 Agent 工程的正經事。

## 6. Agent vs Workflow（何时該用哪個）

| | Workflow（固定流程） | Agent（動態決策） |
|---|---|---|
| 步驟 | **預先寫死** A→B→C | **LLM 動態決定**下一步 |
| 適用 | 流程**穩定、已知** | 任務**多變、需判斷** |
| 成本/控制 | 便宜、可預測 | 貴、需約束 |
| 建議 | **能寫死就寫死** | 只在「**必須**讓 LLM 決策」處用 Agent |

> **心智模型**：**Workflow 是「鐵軌」，Agent 是「自駕」。**
> 多數生產應用＝**鐵軌為主、自駕為輔**——把不确定的環節才交給 Agent，**不要把整個系統都做成自駕**。
