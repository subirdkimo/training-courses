# C2 講稿 — RAG 基礎

> 對應 `class-02-content.md`；build 注入 `addNotes()`。每節【銜接】→【講解要點】→【demo】→【Q&A】。

## §1 這堂要解決什麼
【銜接】「C1 讓 LLM 可控，但它只有『你餵它』的知識——私域、最新資料它沒有。今天教它『開放書考』。」
【講解要點】（4 分鐘）RAG=檢索+生成：先查書（向量庫）再寫答案（LLM）。心智模型：開放書考，成績取決於「翻到對的書頁」。
【demo 提示】—
【Q&A】問「RAG 和直接塞全文件進 prompt 差在哪？」→ 答：全文件=token 爆+召回稀釋；RAG 只塞相關片段。

## §2 全流程圖
【銜接】「先記住地圖，再拆每一站。」
【講解要點】（4 分鐘）帶圖走：文件→切塊→embedding→向量庫；問題→檢索→組 prompt→answer。指出 5 個決策點。
【demo 提示】貼全流程圖，指每一站。
【Q&A】問「為什麼 embedding 要做兩次？」→ 答：存文件一次、查問題一次，同一套坐標系才能比距離。

## §3 切塊策略
【銜接】「第一站就決定 RAG 好不好——切塊。」
【講解要點】（8 分鐘）chunk size 太小碎/太大雜訊；建議 200-800 token；overlap 10-20% 防斷開；語義/結構切塊優於固定長度。
【demo 提示】示範「一句話被切成兩塊」導致檢索失敗的例子。
【Q&A】問「怎麼選切塊大小？」→ 答：先依結構（段落/小標），不夠再語義切。

## §4 Embedding 模型
【銜接】「文字怎麼變成『可比的坐標』？」
【講解要點】（6 分鐘）embedding=把意思翻成向量；選 small（1536 維、便宜）為主；強調存檢要用同一套。
【demo 提示】—
【Q&A】問「為什麼不能存 A 套、查 B 套？」→ 答：坐標系不同，距離沒有意義。

## §5 向量庫
【銜接】「存這些向量放哪？」
【講解要點】（5 分鐘）Chroma（桌上型、本課用）/PgVector（放進現有 PG）/Qdrant/Milvus（中央圖書館）；選法「先簡單、量大了遷」。
【demo 提示】—
【Q&A】問「生產一定用 Chroma 嗎？」→ 答：不，量大了遷 PgVector/Qdrant；架構同。

## §6 組 prompt
【銜接】「檢索到片段後怎麼用？」
【講解要點】（6 分鐘）明確標註【資料】＋要求「只依據資料回答，沒有就說不確定」→ 減幻覺。
【demo 提示】貼 system 限制句；對比「沒有限制→LLM 拿舊知識補＝幻覺」。
【Q&A】問「top-k 取幾個？」→ 答：先 3–5 看效果，太小漏、太大稀釋。

## §7 評估召回
【銜接】「怎麼知道 RAG 好？」
【講解要點】（6 分鐘）品質=檢索分×生成分（乘法）；Recall（檢索到沒）+Faithfulness（有沒有胡說）；列 4 種失敗模式。
【demo 提示】—
【Q&A】問「怎麼量 recall？」→ 答：標準答案所在塊有沒有進 top-k。

【講解要點】（6 分鐘）≥10 段文件、切塊+embedding+Chroma、3-5 測試問題、組 prompt 出 answer、核「只依據資料」。
【demo 提示】貼 lab-02.md。
