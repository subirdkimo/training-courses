# C4 講稿 — Agent 與多步推理

> 對應 `class-04-content.md`；build 注入 `addNotes()`。每節【銜接】→【講解要點】→【demo】→【Q&A】。

---

## §1 這堂要解決什麼
【銜接】「C3 是『一次』工具；C4 是『一串』工具且 LLm 自己決定下一步——這就是 Agent。但沒約束的迴路=失控。」
【講解要點】（5 分鐘）Agent 三要件：做事（C3 已給）+會收手（停止）+出錯會換（重試）。驗收口：3+ 步 ReAct＋1 次重試＋正確停止的 trace。
【demo 提示】—
【Q&A】問「Agent 和 workflow 差在哪？」→ 答：步驟固定=workflow；LLM 動態決定=agent。

## §2 ReAct 迴路
【銜接】「看『想一步→做一步→看結果→再想』長什麼樣。」
【講解要點】（8 分鐘）帶訂機票例走 4 步（search→price→seat→停）；講 Thought/Action/Observation 三角；強調「讀 Observation 再決策」。
【demo 提示】貼 trace 表，逐步口述每一步的 LLM 決策。
【Q&A】問「每步都要 LLM 決定嗎？」→ 答：是，這就是和寫死流程的差別（workflow 不需要）。

## §3 三大約束
【銜接】「本節是 Agent 能不能上生產的差別。」
【講解要點】（10 分鐘）停止條件（目標/最大步數/成本閘門/無進展）；重試（有上限+改策略）；記憶（歷史+摘要）。強調「三缺翻車」。
【demo 提示】貼 run agent 的 max_steps+cost 檢查片段。
【Q&A】問「成本閘門怎麼設？」→ 答：累積 token/費用超門檻就停+報警（C0 估算法）。

## §4 工具選擇與決策
【銜接】「Agent 聰明不聰明，看選工具的決策。」
【講解要點】（6 分鐘）品質差 vs 好對照；技巧：先規劃再執行、description 寫好、每步只給相關子工具集。
【demo 提示】—
【Q&A】問「先規劃再執行怎麼做？」→ 答：讓 LLM 前列 3-5 步計畫，再逐步執行（planning-then-acting）。

## §5 失控案例
【銜接】「5 個失控案例，避坑。」
【講解要點】（6 分鐘）死循環/成本爆炸/誤操作（高危動作要人審）/無限思考/忽略 Observation。強調修法是加約束、不是換更大模型。
【demo 提示】貼一段「死循環 trace」（同工具重打 5 次）。
【Q&A】問「高危動作怎麼辦？」→ 答：加人工確認門（C6 講），高危 action 不讓 LLM 直接執行。

## §6 Agent vs Workflow
【銜接】「何時該用哪個，一次講清。」
【講解要點】（4 分鐘）鐵軌 vs 自駕；多數生產=鐵軌為主、自駕為輔；只在必須讓 LLM 決策處用 Agent。
【demo 提示】並排兩張表。
【Q&A】問「整個系統都做成 agent 行嗎？」→ 答：不建议，成本高+不可控；能寫死就寫死。

## §7 本卡 Lab
【銜接】「作業：3+ 步 ReAct＋1 次重試＋1 次停止。」
【講解要點】（6 分鐘）查天氣→判斷帶傘→排提醒；加最大步數+成本記錄；故意讓工具失敗驗證重試/換路；驗證會停。
【demo 提示】貼 lab-04.md。
【Q&A】問「證據要含什麼？」→ 答：3+ 步完整 trace（含 1 次錯誤重試+1 次停止判定）。
